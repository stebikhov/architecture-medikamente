# Архитектура «Медикаменте» — проектная работа 10-го спринта

Разбираем, как «Медикаменте» сейчас обращается с конфиденциальными данными, что предлагаем изменить и в каком порядке это делать. Целевая архитектура описана в C4, поверх неё — Privacy by Design, единая классификация данных, оценка узких мест миграции и план переключения.

## 2. Единые сокращения на диаграммах

### 2.1. Классификация данных

| Класс                          | Тег          | Идентификатор в системе | Зона по умолчанию          | Основная мера                                  |
| ------------------------------ | ------------ | ----------------------- | -------------------------- | ---------------------------------------------- |
| C1. Публичные                  | Публичные    | `pd:public`             | Anonymized                 | Не требуется                                   |
| C2. Внутренние                 | Внутренние   | `internal`              | Pseudonymized              | Разграничение по роли                          |
| C3. ПДн                        | ПД(общие)    | `pd:general`            | Pseudonymized / Restricted | Полевое шифрование, маскирование, аудит        |
| C4. Специальные ПДн (здоровье) | ПД(здоровье) | `pd:special`            | Restricted                 | Полевое шифрование, ABAC, аудит каждого чтения |
| C5. Платёжные                  | ПД(фин.)     | `pd:financial`          | Restricted                 | Токенизация, TLS, обфускация                   |
| C6. Секреты                    | Секреты      | `pd:secret`             | Изолированный контур       | HSM/Vault, ротация                             |

В документах и на диаграммах тег пишется по-русски, в правилах и конфигурациях — машинным идентификатором; полная таблица в Task3 §1.2. Данные без тега считаем неклассифицированными и отправляем в карантин: по умолчанию конфиденциально.

## 3. Как устроено решение целиком

```
Пациент ──► Портал клиента ──┐
Ресепшен ─► Портал ресепшена ┼─► Система записи ─► CRM
Врач ────────────────────────┘         │
                                       ├─► Платёжный шлюз ─► Банк / ККМ
                                       ├─► Сервис уведомлений ─► Пациент, врач
                                       └─► Privacy-контур (PDP/PEP, теги, согласия, сроки, аудит, KMS, DLP)

Источники (1С, Excel, сканы) ─► Staging (вне ClickHouse) ─► Движок классификации (Task6)
                                   ├─► Landing ─► Restricted ─► Pseudonymized ─► Anonymized ─► BI/ML/LLM
                                   └─► Карантин (очередь + изолированная таблица) ─► Data steward (специалист по качеству и классификации данных)
```
